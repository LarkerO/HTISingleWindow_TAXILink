# UnionCashier 接入

正式环境使用本机 `D:\UnionCashier` 的商户开放接口 `/open/v1`（HTISW1 SM2/SM3 签名 + AES-GCM 报文）。两个乘客端只接收后端生成的 `checkoutUrl` 并跳转；到账必须由后端验证签名查询确认，浏览器回跳参数不作为付款凭证。

## 配置

1. 服务端安装 OpenSSL 3 命令行和 PHP openssl/curl 扩展。`CASHIER_OPENSSL` 填可执行文件路径；Windows 可使用 `C:\Program Files\Git\usr\bin\openssl.exe`。确认服务账号有执行权限。
2. 在 UnionCashier 登记商户，生成商户 SM2 密钥，将公钥登记到收银台，取得 API Key 和平台公钥。确认开通普通支付和退款产品，并设置足够的额度及可用游戏支付方式。
3. TAXILink 管理端进入“收银台商户”，选择“总商户（兜底）”并配置启用状态、来源地址、商户号、环境、API Key、商户私钥 PEM、平台公钥 PEM 和完整回跳 URL。来源地址不能带路径。沙箱和正式环境需分别验收。
4. 回跳 URL 使用正在部署的 Vue 或 uni-app H5 根地址下的 `/payment-return`，例如 `https://passenger.example/payment-return`；在 UnionCashier 登记其来源。反向代理需将该路径回退到乘客端 SPA。H5 依据后端追加的 `orderId` 打开对应行程结算页；App 使用系统浏览器付款，回到 App 后自动刷新，也可点击“我已付款，刷新结果”。
5. 选择具体运营公司配置独立商户。公司未启用专属商户时使用总商户；付款时尚未确定承运公司的预付单使用总商户。配置既可在 React 管理端维护，也可在 uni-app 的运营管理台维护。总商户只有平台管理员可配置，公司商户只有所属企业管理员和平台管理员可配置。
6. 关闭 `DEMO_MODE` 后启用正式接入。未配置商户时明确拒绝付款，不降级为演示入账。演示模式仍只产生演示记录。

## 金额与对账

TAXILink 内部以分存储，UnionCashier 以整数游戏币收费。正式报价与最终结算、取消费和未乘车费向上取整到整游戏币，例如 525 分记为 600 分，收银台收 6 游戏币；退款按取整后的最终应收计算。演示模式保留原计费精度。

下单前持久化交易编号、金额和商户配置快照，网络超时后复用同一编号。乘客重复点击复用未完成的订单；失效后可重新发起。预付确认到账后才进入候补队列。收银台结果必须匹配商户、环境、挑战、订单号、金额与签名。

独立 `cashier-reconciler` 进程每 10 秒扫描未确认交易和需退款订单，不阻塞调度进程。行程完结、取消或失败时的多付款按原交易商户原路退款，退款得到确认后才更新已付金额。退款请求先持久化，再以固定编号重试；部分退款与多笔补款各自记录。交易及退款不依赖用户停留页面。

API Key 和私钥不从配置读取接口返回。数据库中的配置及原交易快照包含服务端密钥，数据库备份需限制访问。轮换或停用收银台密钥前，先处理完旧交易和退款；旧交易不会改绑新商户。收银台拒绝退款、余额不足或请求持续处理中时，保留待退款状态和原请求编号，在收银台核查后处理，不在本地伪造成功。历史演示记录不会转为正式付款。

## 本地验证

- `npm test`：领域、安装和 OAuth 回归。
- `npm run build`：管理端和 Vue 乘客端类型检查与生产构建。
- `npm run test:cashier`：本机临时 HTTP 收银台执行完整双向签名协议测试，不连接正式服务、不扣款。需 OpenSSL 3；Windows 先设置 `$env:CASHIER_OPENSSL = 'C:\Program Files\Git\usr\bin\openssl.exe'`。
- uni-app H5 使用 HBuilderX 编译；App 需在对应调试基座或真机完成浏览器跳转、返回刷新验收。
